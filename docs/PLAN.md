> 변경 이유: 목표는 **특정 재난이 아닌 범용 재난 대응**. v4는 검증 과정에서 쓰나미 비중이 커졌으므로 이를 걷어내고, `docs/VALIDATION.md`(V1~V23)의 결과를 반영한다.

## Context

- 결정 사항: Android 네이티브(Kotlin), 서울 먼저 + 국가 어댑터로 다국가 확장, 주력 코딩 도구 Claude Code(Muse Code는 1~2개 작업). 민방위(공습)는 @CV 답변 전까지 제외.
- 심사: Impact / Meta AI Tooling("beyond a basic integration") / Technical / Demo. FAQ 금지: 전쟁·정치, Basic RAG.

## 범용 재난 구조 (핵심)
- **재난 유형은 데이터 주도**: `Hazard`는 고정 목록이 아니라 국가 팩이 제공하는 유형 집합. 서울 MVP = **지진·홍수**, 이후 데이터가 있으면 화재·산사태·화학사고 등을 같은 규칙 테이블에 행 추가로 확장.
- **규칙 테이블 1개**: `hazard → {허용 시설 유형, 금지 경로 속성, 행동 동사, 공식 행동요령 출처}`. LLM이 판단하지 않음.
  | 재난 | 허용 목적지 | 경로 페널티/금지 | 행동 동사 | 근거 |
  |---|---|---|---|---|
  | 지진 | 옥외대피장소(운동장·공원) | — | "건물 밖 넓은 곳으로" (엘리베이터·차량 금지) | V5 행정안전부 |
  | 홍수 | 이재민임시주거시설 중 **지하 제외** | 지하·터널·실내 구간, 침수흔적 구역 | "높은 곳으로, 지하 피하기" (지하주차장·침수로 운전 금지) | V5 행정안전부 |
  | (확장) 기타 | 국가 데이터의 재난 플래그 | 국가별 정의 | 국가별 공식 문구 | 어댑터에서 매핑 |
- **국가 어댑터 + `flag_semantics`**: 일본 GSI = "그 재난을 피하는 장소", 대만 = "이재민 수용 시설"처럼 의미가 다르므로 어댑터가 의미를 명시하고, "피난 장소" 의미가 아닌 플래그는 목적지로 쓰지 않음(V21).
- **일반화 실증**: `build_pack --city <이름>` 한 줄로 다른 도시 팩 생성. 일본 국토지리원 데이터(재난 8종 플래그)로 **도시 1곳**을 추가해 "재난 종류가 늘어도 코드 수정 없이 동작"함을 보임. (특정 재난 데모 아님)

## 핵심 설계 원칙
1. **안전 경로는 결정론**: 보행망 다중 출발점 Dijkstra로 재난별 경로 트리를 빌드 타임에 계산 → 기기에서 오프라인 즉시 조회. (서울 팩 실측 약 1.6~2 MB, V16)
2. **대피소·경로를 생성하지 않음**: 에이전트는 도구가 준 ID만 사용, `PlanValidator`가 강제(`tool_choice`가 auto만 지원되므로 필수, V11).
3. **오프라인 Q&A는 LLM 실시간 생성이 아님**: 폰용 Llama 1B는 골든셋 8/23·"차 타도 돼요?"→"네"로 **부적합**(V13b·V22). → **빌드 타임에 Muse Glimmer(오픈웨이트, Mac)로 "질문 의도 × 재난 × 언어" 답변을 사전 생성·검수**(23/23 안전, V20) → 팩에 포함 → 기기에서는 **결정론 의도 매칭**으로 꺼냄.
4. **3단계 폴백**: ① 캐시된 개인화 계획 ② 망 있으면 Muse Spark 에이전트 ③ 무망이면 오라클 경로 + 사전 생성 답변. 어느 경우든 첫 화살표는 즉시.
5. **수치 기준**: 도보 1.0 m/s(소방청), 계단 회피 프로필 0.5 m/s. "휠체어"가 아니라 **"계단 없는 경로"**로만 표기(V23).

## 아키텍처
```
[빌드 타임 · Python pipeline/]
 OSM 보행망(layer·indoor·level 태그 포함, V19) + 국가 대피소 데이터 + 침수흔적도(홍수) + 인구 격자
  → 규칙 테이블로 재난별 목적지·엣지 비용 → 다중 출발점 Dijkstra → pack_<city>.bin (재난별 next_node·dist·shelter)
  → Glimmer(llama-server, 오프라인)로 의도×재난×언어 답변 생성 → 골든셋 채점·사람 검수 → pack_<city>.sqlite
  → 부산물: 데이터 이상치 리포트, 재난별 목적지 차이·사각지대 수치(피치용)

[기기 · 평시 (망 있음)]
 WorkManager 위치 수집 → 생활 구간 클러스터링 → 계획 에이전트 (muse-spark-1.3 tool calling)
   도구: get_shelters · route_oracle · get_guideline · get_profile · save_plan
   → 개인화 계획(가족 재회 지점, 계단 없는 경로, 과밀 회피) → PlanValidator → 캐시

[기기 · 경보]
 트리거(재난 유형 버튼 / 위젯 / 시뮬레이션)
  → ① GPS(또는 마지막 위치) → 최근접 노드 → 재난별 경로 트리 → 화살표·거리·행동 동사 (즉시, 오프라인)
  → ② 개인화 계획: 캐시 → 에이전트(망) → 오라클 기본 계획(무망)
  → ③ Q&A: 망 있으면 Muse Spark(+ Voice Transcribe) / 없으면 사전 생성 답변(의도 매칭)
```

## 피치 수치 (검증 기반, 조건 문구 포함)
- 확정: 직선거리로 고른 "가장 가까운 대피소"가 실제 보행 기준으로는 틀린 경우 **21~28%**, 틀릴 때 p90 약 600~700 m 더 걸음 (V9).
- 확정: 공식 근거 — 행정안전부 "피난 가능한 장소와 길을 사전에 숙지", 서울시 "생활거점 주변 대피소 숙지" (V5·V10).
- **키 수신 후 계산**: 서울에서 **지진 목적지 ≠ 홍수 목적지인 인구 비율**(V9b 방식), 홍수 시 지하 경유를 피하면 경로가 바뀌는 비율(V19, 현재 OSM 대용 6.1%), 공식 데이터 기준 출발 지연 단축 효과(V4d 방식).
- 주장하지 않을 것: "재난 유형별 대피소 안내 자체가 새롭다"(개인 앱 존재, V10b), "보행망 사각지대 분석이 새로운 지식"(선행 연구 존재, V14b), "휠체어 경로"(V23).
